# Backend Roadmap (варианты и структура)

Документ собран как набор задач и подзадач без навязывания единственного решения.
В каждом разделе есть варианты, из которых можно выбрать подходящий.

## 1. База данных и модель домена

### Главная задача
Сделать структуру данных устойчивой к росту проекта и изменениям требований.

### Подзадачи
- Определить обязательные и необязательные поля для `Board`, `Thread`, `Post`.
- Зафиксировать поведение удаления для всех связей (`CASCADE`, `SET_NULL`, `SET_DEFAULT`).
- Определить ограничения целостности (уникальность, длина, допустимые значения).
- Описать стратегию миграций данных (что автоматизируется через data-migrations).
- Уточнить стратегию архивирования (только доска-архив или дополнительные статусы).

### Варианты
- Строгая схема: больше обязательных полей, меньше неоднозначностей.
- Гибкая схема: больше `blank/null`, быстрее итерации на старте.

## 2. Аутентификация, авторизация и роли

### Главная задача
Формализовать доступ: кто, когда и какие действия может выполнять.

### Подзадачи
- Описать матрицу прав для ролей: гость, пользователь, VIP, модератор, админ, владелец, заблокированный.
- Разделить сценарии аутентификации и авторизации в API.
- Определить поведение заблокированного аккаунта (что именно запрещено).
- Зафиксировать жизненный цикл пользователя: регистрация, активация, восстановление, деактивация.
- Решить, где хранить логику прав: только backend или дублировать на frontend (UI-ограничения).

### Варианты
- Роли через группы Django (проще старт).
- Роли + granular permissions (гибче, но сложнее поддержка).

## 3. Контент и модерация

### Главная задача
Описать полный жизненный цикл досок, тредов и постов.

### Подзадачи
- Определить статусы контента (активный, скрытый, удаленный, архивный).
- Зафиксировать действия модерации: удаление, закрытие, закрепление, перенос.
- Описать работу репортов: создание, обработка, результат.
- Сформировать правила загрузок медиа: допустимые типы, размеры, хранение.
- Определить поведение при удалении автора (анонимизация, сохранение постов, скрытие).

### Варианты
- Soft delete (лучше для аудита и откатов).
- Hard delete (проще реализация и меньше хранения).

## 4. Поиск, фильтрация, сортировка

### Главная задача
Сделать контент быстро находимым и удобным для навигации.

### Подзадачи
- Определить типы сортировки: новые, активные, популярные.
- Определить фильтры для MVP (доска, тема, автор, дата, теги).
- Зафиксировать пагинацию и лимиты (размер страницы, max limits).
- Определить минимальные требования к поиску (по заголовку, тексту, тегам).
- Описать UX-правила для пустых результатов и ошибок фильтрации.

### Варианты
- Базовый поиск средствами ORM/БД.
- Расширенный поиск (full-text или отдельный движок) на следующем этапе.

## 5. Безопасность и антиабьюз

### Главная задача
Снизить риск спама, злоупотреблений и типовых уязвимостей.

### Подзадачи
- Добавить rate limit на чувствительные действия (логин, постинг, репорты).
- Определить правила валидации и очистки контента.
- Продумать защиту загрузок файлов (тип, размер, имя, проверка).
- Зафиксировать базовые меры против XSS/CSRF/bruteforce.
- Определить минимальный аудит действий модерации и админов.

### Варианты
- Минимальная защита для MVP.
- Расширенная защита (лимиты + антиспам + расширенный аудит).

## 6. API-контракт и тестирование

### Главная задача
Сделать API предсказуемым для frontend и стабильным в развитии.

### Подзадачи
- Определить единый формат успешных ответов и ошибок.
- Решить вопрос версионирования API (`v1` или без версии на старте).
- Зафиксировать обязательные проверки прав на уровне endpoint-ов.
- Определить минимальный набор тестов (auth, permissions, CRUD, moderation).
- Определить подход к документированию API (вручную или автогенерация).

### Варианты
- Ставка на интеграционные тесты (быстрый практический контроль).
- Комбинация unit + integration + permission tests (дольше, но надежнее).

## 7. Операционка: окружения, деплой, поддержка

### Главная задача
Подготовить проект к стабильной работе вне локальной машины.

### Подзадачи
- Разделить настройки dev/prod (секреты, debug, хосты, CORS).
- Определить хранение медиа и стратегию бэкапов.
- Описать процедуру миграций на проде.
- Определить базовый мониторинг ошибок и логов.
- Сформировать план восстановления после сбоев.

### Варианты
- Простая схема для pet-проекта (минимум инфраструктуры).
- Более надежная схема (отдельные окружения, внешнее хранилище, бэкапы).

## 8. Планирование этапов (шаблон)

Используй этот шаблон для выбора собственного темпа:

- Этап 1 (MVP): минимальный рабочий контур.
- Этап 2: усиление прав/модерации/качества API.
- Этап 3: масштабирование поиска, надежности и инфраструктуры.

Каждый этап можно вести по чек-листу:
- [ ] Выбраны варианты по разделу.
- [ ] Зафиксированы решения в отдельной заметке.
- [ ] Реализован минимум функционала.
- [ ] Проверено тестами/ручными сценариями.
- [ ] Обновлена документация.
