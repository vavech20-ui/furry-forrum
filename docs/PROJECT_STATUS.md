# Статус проекта: сделано и в работе

Актуально по коду в репозитории (бэкенд `forum/`, фронт `src/`).

## Уже реализовано (можно считать готовым)

### Backend (Django / DRF)

- **Модели:** `Board`, `Thread`, `Post` в `boards/models.py` (связи, поля треда/поста, валидация расширений видео: mp4, webm, mov).
- **Связь тред → доска:** `Thread.board` с `on_delete=PROTECT` (без архивной доски по умолчанию; доску с тредами нельзя удалить).
- **Миграции:** каталог `boards/migrations/` (в т.ч. изменение поля `board` у `Thread`).
- **API досок:** `BoardViewSet` — `GET` список/деталка для всех (`AllowAny`); `POST`/`PUT`/`PATCH`/`DELETE` — только админ (`IsAdminUser`). Префикс `/boards/`.
- **API тредов:** пути `/boards/threads/`, `/boards/threads/<id>/`. `GET` — без JWT; `POST`/`PUT`/`PATCH` — с JWT (`IsAuthenticated`), автор в `perform_create`; **`DELETE` — только админ** (`IsAdminUser`).
- **API постов:** пути `/boards/posts/`, `/boards/posts/<id>/`. Все действия требуют JWT (глобальный `IsAuthenticated`, своего `get_permissions` нет).
- **Сериализаторы:** `BoardSerializer`, `ThreadSerializer`, `PostSerializer`.
- **Аутентификация:** Djoser + JWT (`/auth/`, `rest_framework_simplejwt`).
- **Профиль пользователя:** `CustomUserSerializer` — в ответе `/auth/users/me/` есть `is_staff`, `is_superuser` (для админ-UI на фронте).
- **Регистрация:** `SEND_ACTIVATION_EMAIL = False` — аккаунт сразу активен, письма не отправляются (dev-заглушка).
- **CORS:** origin `http://localhost:5173`.
- **Медиа:** `MEDIA_URL`, `MEDIA_ROOT`; в `DEBUG` раздача через `forum/urls.py`.
- **Админка Django:** `/admin/` подключён (модели `boards` в `admin.py` не зарегистрированы).

### Фронтенд (Vite + React)

- **API-слой:** `src/api/client.js` (axios, JWT, refresh при 401), `auth.js`, `boards.js`; базовый URL — `VITE_API_URL` или `http://127.0.0.1:8000`.
- **Аутентификация:** JWT в `localStorage`, `AuthContext`, логин/регистрация через API; хелпер `isAdmin(user)`.
- **Маршруты:**
  - `/` — список тредов, фильтр по доске;
  - `/login`, `/register`;
  - `/threads/:id` — тред, посты, удаление треда (админ);
  - `/create-thread` — создание треда (multipart, обязательно `img`);
  - `/create-board` — создание доски (только админ);
  - `/activate/:uid/:token` — заглушка (активация отключена на бэкенде).
- **Посты в треде:** `CommentSection` — `GET`/`POST`/`DELETE` через API (нужен вход).
- **UI:** общие стили `src/styles/global.css`, шапка с навигацией.

### Документация

- `docs/BACKEND_ROADMAP_OPTIONS.md` — план и варианты по бэкенду.
- `docs/API_FOR_FRONTEND.MD` — HTTP API и согласование с фронтом.
- `.env.example` — пример `VITE_API_URL`.

## Сделано не до конца / требует доведения

### Backend

- **Права на посты:** публичное чтение постов гостю не настроено; любой авторизованный может читать/удалять любой пост (нет проверки автора).
- **Фильтр постов по треду:** API отдаёт все посты; фронт фильтрует на клиенте.
- **Приложение `users`:** своих моделей/маршрутов нет (`users/urls.py` пустой).
- **Админка:** `boards/admin.py` пустой — досок/тредов/постов нет в `/admin/` без регистрации моделей.
- **Почта:** SMTP и активация закомментированы; для продакшена нужна отдельная политика.

### Фронтенд

- **Редактирование тредов** с UI не реализовано (API `PUT`/`PATCH` есть).
- **Редактирование досок** только через API/админку, отдельной страницы нет.
- **Профиль пользователя** (`/auth/users/me/` PATCH) — страницы нет.

### Инфраструктура и качество

- **`SECRET_KEY`** — заглушка в `settings.py`.
- **Автотесты** под API и права не покрыты (заготовки `tests.py`).
