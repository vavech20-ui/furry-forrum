# Статус проекта: сделано и в работе

## Уже реализовано (можно считать готовым)

### Backend (Django / DRF)

- **Модели:** `Board`, `Thread`, `Post` в `boards/models.py` (связи, поля для треда и поста, валидация расширений видео).
- **Миграции:** в том числе data-migration с гарантированной архивной доской `id=1` (`0004_ensure_archive_board`).
- **API досок:** `BoardViewSet` — список и просмотр для всех (`AllowAny`), создание/изменение/удаление — только админ (`IsAdminUser`). Маршруты под префиксом `/boards/`.
- **API постов:** `PostViewSet` + ручные пути `/boards/posts/` и `/boards/posts/<id>/`.
- **API тредов:** `ThreadViewSet` + пути `/boards/threads/` и `/boards/threads/<id>/`. Список и просмотр — без JWT (`AllowAny`); создание/изменение/удаление — с JWT (`IsAuthenticated`); автор при создании выставляется в `perform_create`.
- **Сериализаторы:** `BoardSerializer`, `PostSerializer`, `ThreadSerializer`.
- **Аутентификация:** подключены `djoser`, JWT (`rest_framework_simplejwt`), маршруты `/auth/` (Djoser + JWT).
- **CORS:** разрешён origin фронта `http://localhost:5173`.
- **Админка Django:** путь `/admin/` подключён (сами модели `boards` в админке пока не зарегистрированы — см. ниже).

### Документация

- `docs/BACKEND_ROADMAP_OPTIONS.md` — план и варианты по бэкенду.
- `docs/API_FOR_FRONTEND.MD` — шпаргалка по API для **локальной разработки** (при добавлении эндпоинтов стоит дополнять раздел про треды).

### Фронтенд (Vite + React)

- **Маршрутизация:** `react-router-dom` — главная, регистрация, вход, создание треда.
- **UI:** заголовок, список тредов (компоненты), формы регистрации/логина/создания треда, стили.
- **Зависимость `axios`** в `package.json` (готова к подключению к API).

## Сделано не до конца / требует доведения

### Backend

- **Права на посты:** у `PostViewSet` нет своего `get_permissions()` — действует глобальное `IsAuthenticated` для всех действий; публичное чтение постов (если нужно гостю) явно не настроено.
- **Медиа:** в `forum/forum/urls.py` в `DEBUG` подключается раздача `MEDIA_URL` / `MEDIA_ROOT`, но в `settings.py` переменные **`MEDIA_URL` и `MEDIA_ROOT` сейчас не заданы** — загрузки и URL к файлам нужно согласовать с настройками.
- **Приложение `users`:** заготовка без своих моделей и API в `users/urls.py` (пустые `urlpatterns`).
- **Регистрация через Djoser и активация:** в настройках включено `SEND_ACTIVATION_EMAIL`; письма уходят в консоль (`EMAIL_BACKEND`), но полный сценарий «регистрация → активация → вход» нужно проверить и описать под выбранный флоу.
- **Админка:** `boards/admin.py` пустой — модели не видны в `/admin/` без регистрации.

### Фронтенд

- **Вход и регистрация** сейчас завязаны на **`localStorage`**, а не на `/auth/` и JWT бэкенда — с реальным API не связаны.
- **Треды** на главной и в форме создания тоже хранятся в **`localStorage`**, а не запрашиваются/создаются через API (бэкенд для тредов уже есть).
- **`AuthContext`** хранит только объект «пользователь» в памяти после локального «логина», без токенов и без запросов к серверу.

### Инфраструктура и качество

- **`SECRET_KEY`** в `settings.py` — заглушка; для любого общего/прод окружения нужна своя политика секретов.
- **Тесты:** автотесты под новые эндпоинты и права не описаны как обязательный слой (есть только заготовки `tests.py` в приложениях).
